# message-chapters

Плагин Claude Code для **Claude Desktop** (вкладка Code): каждое ваше сообщение
становится главой во встроенном оглавлении сессии. В оглавлении видно начало каждого
сообщения, клик по нему переносит к этому месту переписки — как навигация по своим
сообщениям в ChatGPT.

Глава встаёт сразу под сообщением, у любого ответа (и у «Привет»). Модель для этого
не вызывается и ничего не пишет: лишних запросов нет, в контекст добавляется только сам
вызов главы и короткий ответ на него — десятки токенов.

## Как устроено

**Откуда берётся оглавление.** Обработчик инструмента `mcp__ccd_session__mark_chapter`
в десктопе ничего не хранит — только отвечает «Chapter marked». Оглавление строит
интерфейс (он грузится с claude.ai) по вызовам этого инструмента **в переписке**. Поэтому
вызвать инструмент из плагина напрямую (`$.tool.call`) бесполезно: такой вызов в
переписку не попадает, и главы не видно. Нужно, чтобы вызов оказался в ответе модели.

**Как плагин туда его ставит.** Ответ модели идёт шагами (`turn.step`): каждый шаг —
один запрос к модели; если шаг закончился вызовами инструментов, движок их выполняет и
делает следующий шаг. Плагин отвечает **за модель на первый шаг хода** — одним вызовом
главы, без запроса к API. Движок выполняет его как обычный вызов, записывает в
переписку, и со второго шага отвечает уже настоящая модель.

```
ваше сообщение
   │  prompt.submit: своё? не слэш-команда? не пустое? запомнить главу
   ▼
шаг 0 — отвечает плагин, без модели:
   tool_use mcp__ccd_session__mark_chapter { title, summary }   → глава в оглавлении
   │  движок выполняет вызов: «Chapter marked…»
   ▼
шаг 1 — запрос к модели, обычный ответ
```

- **Название главы** — начало сообщения в одну строку до 39 символов (оглавление
  принимает меньше 40), описание — до 200.
- **Чьи сообщения.** Из поля ввода, с телефона (Remote Control) и из десктопа. Не
  ставятся для уведомлений фоновых задач, сообщений других агентов, сессий и плагинов,
  слэш-команд, пустых сообщений и сообщений, отправленных посреди идущего ответа (они
  вливаются в текущий ход).
- **Только Claude Desktop.** Плагин проверяет, есть ли в сессии инструмент глав; в
  терминальном Claude Code его нет, и плагин ничего не делает.
- **Запасной способ.** Если API не примет шаг, сделанный плагином (ход завершится
  ошибкой), до конца сессии плагин переключается на запасной способ: дописывает вызов
  главы в конец шага модели, который и так вызывает инструменты (лишнего запроса тоже нет,
  но глава встаёт после начала ответа, а у чисто текстовых ответов её не будет). Об этом
  всплывает уведомление; сообщение, на котором упало, нужно отправить ещё раз.
- **Почему главы, а не своя панель.** Плагин может нарисовать список сообщений, но
  перематывать переписку десктоп плагинам не даёт (`$.ui.scroll` отвечает
  `transcript not scrollable here`).
- **Лог.** `%LOCALAPPDATA%\MessageChapters\message-chapters.log` — каждая поставленная
  или пропущенная глава с причиной; последние 2000 строк, общий для всех сессий.
- **Ограничения.** Главы появляются только у новых сообщений — к уже отправленным их
  не добавить. Модель видит вызов главы в своей истории как свой.

Код: `hooks/register.ts` — хуки (запомнить главу, ответить первым шагом, запасной
способ), `hooks/chapters.ts` — чистые функции (чьё сообщение, название главы, обрезка лога).

## Установка из релиза

1. Скачать `MessageChapters-vX.Y.Z.zip` со страницы релизов и распаковать в
   `D:\apps\MessageChapters` (внутри должны быть `.claude-plugin\plugin.json` и `hooks\`).
2. В `~/.claude/settings.json` добавить папку в переменную окружения:
   ```json
   { "env": { "CLAUDE_CODE_PLUGIN_DIRS": "D:\\apps\\MessageChapters" } }
   ```
   Несколько папок разделяются `;`.
3. Открыть новую сессию в Claude Desktop — плагин подхватится сам.

## Установка из исходников

Нужны Claude Desktop (из него берётся движок для проверок) и PowerShell 7.

```powershell
.\deploy.ps1
```

Скрипт прогоняет `claude plugin validate` и `claude plugin test`, ставит плагин в
`D:\apps\MessageChapters` (рядом `SOURCE.txt` с версией и коммитом) и добавляет эту папку
в `CLAUDE_CODE_PLUGIN_DIRS` в `~/.claude/settings.json` (перед изменением делает копию
`settings.json.bak`). Новые сессии подхватят плагин, уже открытые — после перезапуска.

## Разработка

- Тесты: `claude plugin test .` (движок Claude Desktop:
  `%APPDATA%\Claude\claude-code\<версия>\<hash>\claude.exe` — `claude` из PATH бывает старее).
- Проверка: `claude plugin validate .`
- Обновление: поднять версию в `.claude-plugin/plugin.json`, дописать `CHANGELOG.md`,
  закоммитить, `.\deploy.ps1 -Release`.
